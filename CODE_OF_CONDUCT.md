# Wanyrix Code of Conduct

**Adopted: the [Rust Code of Conduct](https://www.rust-lang.org/policies/code-of-conduct)**
(adopted by the Wanyrix project on 2026-09-22 as part of the governance bundle,
issue #119). The operative rules are reproduced below so this file stands alone;
the canonical text at the link above is the authority. If the Rust CoC is updated
upstream, this file is re-synced by a PR referencing an issue.

## Scope

This conduct standard applies to this repository's community spaces: issues, pull
requests, code review, and any project-run discussion channel or event. It applies to
everyone in the project — maintainer and contributors alike.

## Our standards — the operative rules

- We are committed to providing a friendly, safe and welcoming environment for all,
  regardless of level of experience, gender identity and expression, or cultural
  background.
- Please avoid using overtly sexual aliases or other nicknames that might detract from
  a friendly, safe and welcoming environment for all.
- Please be kind and courteous. There's no need to be mean or rude.
- Respect that people have differences of opinion and that every design or
  implementation choice carries a trade-off and numerous costs. There is seldom a
  right answer.
- Please keep unstructured critique to a minimum. If you have solid ideas you want to
  experiment with, make a copy of the repo and start there.
- We will exclude you from interaction if you insult, demean or harass anyone. That is
  not welcome behaviour. We interpret the term "harassment" as including the
  definition in the [Citizen Code of Conduct](https://github.com/stumpsyn/policies/blob/master/citizen_code_of_conduct.md);
  if you have any lack of clarity about what this might involve, please speak with the
  moderation contact below.
- Likewise any spamming, trolling, flaming, baiting or other attention-stealing
  behaviour is not welcome.

## Moderation

This project is in the **single-maintainer phase** — the honesty-first statement of
that is better than pretending a committee exists
([`GOVERNANCE.md`](GOVERNANCE.md) §3 records the transition trigger to a maintainers
council, at which point this section gains a moderation team).

- **Report to:** the maintainer, [@Roy-Wanyoike](https://github.com/Roy-Wanyoike) —
  via a direct GitHub message, or via [GitHub private vulnerability reporting](https://github.com/Roy-Wanyoike/wanyrix/security/advisories/new)
  if you prefer the report to stay private (enabled 2026-09-22).
- **What happens:** reports are acknowledged, reviewed against the rules above, and
  handled with the graduated responses of the Rust CoC moderation policy — clarify,
  warn, temporary exclusion, permanent exclusion — with the reason recorded.
- **Conflicts of interest:** a report about the maintainer cannot be moderated by the
  maintainer alone; in that case the report is escalated to the Rust moderation team
  as the adopted standard's stewards, and this document gains a project moderation
  team at the council transition (trigger in [`GOVERNANCE.md`](GOVERNANCE.md) §3).
- **Appeals:** an excluded party may appeal once, in writing, to the same contact; the
  appeal decision is final for the single-maintainer phase and re-heard by the council
  after the transition.
